A website backup is a complete copy of your site's files and database that you can restore if something goes wrong. Good backup and recovery means backing up automatically, daily for busy sites and at least weekly for small ones, storing copies away from the web server, keeping several versions, and testing restores regularly. It protects you from hacking, server failure, bad updates and simple human mistakes, which sooner or later happen to every website.

Why every website needs backups

  • Hacking and malware: restore a clean copy instead of rebuilding.
  • Failed updates: roll back when a plugin or theme update breaks the site.
  • Human error: recover deleted pages, products or settings.
  • Hosting problems: survive server failure or a host shutting down.
  • Peace of mind: make changes knowing you can undo them.

What to back up

A full backup includes the database, which holds content, orders and users, and the files, which hold themes, plugins, uploads and configuration. On WordPress, both are essential. For ecommerce, the database changes every time someone places an order, so it needs more frequent backups.

How often to take a website backup

Type of siteSuggested frequency
Small brochure site, rarely updatedWeekly, plus before every change
Blog or business site updated oftenDaily
Ecommerce store or booking siteDaily or more often, ideally real-time database backups
Before any update or redesignAlways, manually

The 3-2-1 rule

Keep three copies of your data, on two different kinds of storage, with one copy off-site. In practice, that means the live site, a backup with your host and another in separate cloud storage under a different account. As a result, one compromised account or failed provider cannot wipe out everything.

Testing recovery

  1. Every few months, restore a recent backup to a staging site.
  2. Check pages, images, forms, logins and checkout.
  3. Time how long the restore takes.
  4. Write down the steps so anyone on the team can follow them.
  5. Store login details for hosting, DNS and backup storage safely.

A backup you have never restored is only a hope. For broader planning, see CERT-In guidance on incident readiness.

What backups cost

Many hosts include daily backups, and free WordPress plugins can send copies to cloud storage. Managed off-site backups with one-click restores usually cost a small monthly fee. Backups are also part of most maintenance plans; see our website maintenance cost guide.

Common backup mistakes

First, storing backups only on the same server as the site. Next, never testing a restore. Then, backing up files but not the database. After that, keeping only one version, so an infection is copied into the backup. Finally, losing access because the backup account is in a former employee's name.
